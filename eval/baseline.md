# Super-DAISY classic — baseline evaluation

Reference numbers for the "classic" SuperDaisy configuration (all defaults
from `lib/super_daisy/components/`), captured before any modern-LM
component swaps. Future variants compare against these numbers; thresholds
for accepting/rejecting a swap are described in
[SUPER_DAISY.md](../SUPER_DAISY.md).

How this was produced:

```
bin/eval --personality "daisy11 original freepascal/MEM.DSY" \
         --label mem.dsy \
         --report eval/baseline_mem.md --data eval/baseline_mem.json
bin/eval --personality fortune-haiku-3-5-250.DSY \
         --label fortune-haiku-3-5-250 \
         --report eval/baseline_fortune.md --data eval/baseline_fortune.json
gnuplot eval/baseline.gp
```

30 prompts (`eval/prompts.txt`) × 10 seeds = 300 trials per corpus.

## Headline numbers

| metric | MEM.DSY (92 sentences, 619 words) | fortune-haiku (250 sentences, 11974 words) |
|---|---|---|
| **fallthrough rate** (unconditioned-Markov fallback) | **0.767** | **0.810** |
| **ugliness rate** (winner had ugly flag) | 0.087 | **0.840** |
| mean response length (tokens) | 8.0 | 12.2 |
| median response length (tokens) | 9 | 12 |
| distinct-2 (unique bigrams / total) | 0.091 | 0.146 |
| distinct-3 (unique trigrams / total) | 0.120 | 0.169 |
| KL(responses ‖ corpus) bigrams, nats | 0.951 | 0.558 |
| latency p50 (ms) | 16.0 | 27.3 |
| latency p95 (ms) | 16.7 | 28.0 |
| mean attempts per response | 858 | 966 |
| mean kept candidates per response | 2.3 | 0.8 |

Full per-corpus reports: [`baseline_mem.md`](baseline_mem.md),
[`baseline_fortune.md`](baseline_fortune.md). Raw per-trial records in
`baseline_mem.json` / `baseline_fortune.json`.

## What jumps out

1. **Fallthrough dominates both corpora** (77% / 81%). The rejection
   sampler is failing to find any keyword-bearing candidate on most prompts
   and falling through to unconditioned Markov. That fallthrough is *how
   the canonical DAISY non-sequitur happens*, but at these rates the
   keyword filter is barely doing its job. **This is the metric to watch
   most carefully when swapping components** — a PPM upgrade or BM25
   reranker that lifts this to e.g. 50% would meaningfully change her
   character, even if outputs are individually "better."
2. **Ugliness rate is 0.087 on MEM but 0.84 on fortune.** The fortune
   corpus's long, vocabulary-rich sentences trigger the local-cycle and
   length-cap heuristics constantly. Worth noting because *suppressing*
   this rate via a smarter generator would also drift character.
3. **Mean attempts ~860–970** out of `max_candidates=1000`: she's burning
   nearly the entire budget on most calls. Latency is dominated by
   exhausting the attempt cap, not by individual sample cost.
4. **Mean kept candidates is 2.3 on MEM, 0.8 on fortune.** The pool_size=10
   target is essentially never met on fortune. The reranker has very
   little to choose from.
5. **KL(responses ‖ corpus) bigrams = 0.951 / 0.558 nats.** Higher on MEM
   because the small corpus has fewer bigrams and responses concentrate on
   a narrow slice. Use these as anchors: future variants whose KL drifts
   by ~0.3+ nats from these are statistically generating in a
   noticeably different style.
6. **The fallthrough fallback is itself deterministic per seed.** Looking
   at the seed=1 sample table in `baseline_mem.md`, 23/30 responses are
   the same canonical sentence ("the most important thing about life is
   being happy."). Every prompt whose keywords miss converges to that
   sentence because the fallback path enters with the same RNG state.
   That's an artifact of how the orchestrator advances the RNG — not
   character, but worth flagging when reading sample outputs.

## Stop conditions for future swaps

Carry these forward when evaluating PPM / BM25 / temperature / etc:

- **Fallthrough rate drops by more than ~25 percentage points** (e.g. MEM
  goes from 0.77 to <0.52): probably character-altering. Reconsider.
- **Ugliness rate drops to near-zero on fortune** (currently 0.84): means
  we've over-sanitized; her run-ons and cycles are part of the texture.
- **KL(responses ‖ baseline_responses) bigrams > ~0.5 nats**: significant
  style drift. (Future runs will compute against
  `baseline_*_data.json`'s `response_bigrams` field, not against the
  corpus.)
- **Latency p95 regresses > 2× without a compensating quality jump**: bad
  trade.
- **Distinct-2 drops dramatically**: mode collapse, reject.

## Reproducing

Deterministic given the same Ruby version and corpus files. To regenerate
after any change:

```
ruby -Ilib bin/eval --personality "daisy11 original freepascal/MEM.DSY" \
                    --label mem.dsy \
                    --report eval/baseline_mem.md --data eval/baseline_mem.json
ruby -Ilib bin/eval --personality fortune-haiku-3-5-250.DSY \
                    --label fortune-haiku-3-5-250 \
                    --report eval/baseline_fortune.md --data eval/baseline_fortune.json
gnuplot eval/baseline.gp
```
